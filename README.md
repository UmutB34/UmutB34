## Currently Building

### [Korantix](https://korantix.io) — External Domain Security Posture

Korantix helps organizations understand the external security posture of their
domains and email — using only public DNS, TLS and HTTP data. No credentials,
no tenant access, no installed agents.

The focus is on **explainable findings**: every result shows the evidence behind it
and practical remediation guidance, instead of an unexplained score.

| Area | Examples |
|---|---|
| Email security | SPF, DKIM, DMARC, MX, SMTP / STARTTLS |
| DNS | record lookups, propagation, reverse DNS |
| TLS & web security | certificates, security headers, CSP, cookies, CORS |
| Reputation | DNSBL / blacklist checks |

Continuous monitoring and security change intelligence are in active development.

## Engineering Principles

- Architecture should be operable, not just designed.
- Security should be measurable.
- Automation should remove operational friction.
- Monitoring should produce actionable information, not noise.
- Transformation should improve reliability, not simply introduce new tools.
- Technology decisions should support business continuity.

## Career Perspective

My career started at the support desk and in server rooms — installing, fixing and
learning why things break. Over time that became ownership of the infrastructure,
then responsibility for running IT operations across locations, and eventually
leading technology teams, vendors and transformation programs.

That path shapes how I make decisions. A roadmap has to survive contact with
operations, a security control has to be something the team can actually run, and a
new platform has to earn its place by making the environment more reliable. I still
build and test things myself — because good technology leadership depends on
understanding how the technology really behaves.
